## 1. 现状盘点

### 1.1 现有前处理流程（v1.3.x 已交付）

```
Probing（ffprobe 探测）
  → Ocr（时间戳识别，RapidOCR）
  → Sorting（智能排序：文件名时间 + 时间戳交叉验证）
  → UserConfirm（用户确认顺序）
  → Precheck（预检：重叠/缺口/异常）
  → Transcoding（libx264 veryfast CRF18 统一转码）
  → Concat（组内拼接 merged_concat.mp4）
  → Done（证据报告 CSV + 案件登记）
```

## 2. 拍板点（Q 项，待用户确认）

### Q1 硬件编码默认策略（建议：采纳方案 §8）
- 运行时探测顺序：**NVENC → QSV → libx264**（失败逐级回退，日志记录实际编码器）
- **参数等价性评审**（结果可信红线）：NVENC CQ ↔ CRF18 映射实测
  （抽样 SSIM/PSNR + 目检），评审结果写入证据报告（取证留档：实际编码器 + 参数）
- 兼容性底线：任何硬编失败静默回退软编，CI 基线永远跑 libx264

### Q2 重叠自动剪切（方案已拍板 Q-17，确认实施范围）
- 策略：**剪掉后一段开头（保前段完整）**；**默认关闭**，Precheck 检测到
  时间重叠时提示用户是否需要修剪（对话框：修剪 / 保留原样+报告）
- 切点非关键帧：切点前后各 1 GOP 局部重编码，其余流拷贝（-c copy）

### Q3 多通道并行度（建议：组级并行 N=2）
- 组间并行 N=2（磁盘 IO 吞吐实测调参，线程配额不超核数-2）
- 组内仍串行（同组文件同相机，顺序产出）

### Q4 自动命名（建议：采纳方案 §8）
- `<通道>_<yyyyMMdd>_<HHmmss>-<HHmmss>.mp4`（起止取校时后的墙钟时间）
- 通道缺失用组名；**命名映射写入证据报告**（原始名↔输出名可追溯）
- 与 merged_concat.mp4 现行命名共存（单组默认组行为不变）

### Q5 混 fps 恒定帧率（遗留·十五章）
- 组内检测到 fps 差异 >4%：提示用户选择统一帧率（默认组内主导 fps），
  转码加 `-r` 统一；偏差记录进证据报告

### Q6 跨相机混拼参数统一（遗留·十七章）
- 混拼组内分辨率/像素比不一致：按主导参数归一（转码统一 scale + SAR），
  组内偏差提示；拼接产物比例统一

## 4. 验收标准

| 项 | 验收线 |
|---|---|
| 硬编等价性 | 同源抽样段 NVENC vs libx264：SSIM≥0.99 / PSNR≥40dB；目检无可见块状/色偏 |
| 硬编速度 | 同素材转码耗时 ≤ 软编 1/5（4090 级预期 20×+；记录实际倍率） |
| 回退 | 禁用 GPU/驱动异常 → 自动 libx264，结果与 v1 一致 |
| 剪切正确性 | 剪切产物时长 = 理论值 ±1s；播放无花屏；证据报告记录剪切动作 |
| 并行 | 6 组素材组级并行总耗时 < 串行/1.5；进度单调不倒退 |
| 命名 | 映射可追溯（报告原始名↔输出名）；跨天/无校时边界正确 |
| 全回归 | 9 套测试全绿；前处理集成测试（preprocess 170 + e2e 51）覆盖新路径 |

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| NVENC 驱动 API 版本不可用（历史实发） | 试编码探测 + 静默回退 libx264 + 日志；UI 提示"已回退软件编码" |

| UI 改动面大（2000 行 window） | 提示流最小侵入：仅 Precheck 后加对话框分支 |
