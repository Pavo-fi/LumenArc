# 亮度分析与语谱分析：通俗原理讲解

> 面向零基础读者。不讲公式，只用生活类比说明这个软件"到底在算什么"。

---

## 一、亮度分析：把整段视频"称一称明暗"

### 1. 视频的每一帧画面，本质是一张数字表格

把一段监控录像想象成一本厚厚的翻页动画书：每一页（叫一**帧**）就是一张静态照片。
把照片放大再放大，你会发现它其实是由无数小方格（**像素**）组成的，每个像素有自己的明暗：

- **0** = 纯黑
- **255** = 纯白
- 中间值 = 各种灰

有意思的是，监控视频文件里存颜色时，本来就把"**明暗（Y）**"和"**颜色（UV）**"分开存放的——
所以"量明暗"这件事，我们直接拿文件里现成的明暗值（Y 值）就行，不用做任何换算。
（这也解释了为什么我们的分析又快又准：用的是最原始的数据，零转换。）

### 2. 你框的 ROI，就是"只关心这一块地方"

你在画面上画一个矩形或多边形，这叫 **ROI（感兴趣区域）**。
意思很简单："整幅画面我不在乎，我就盯着这一块看。"

- **矩形 ROI**：直接把框内所有像素的明暗值加起来求平均。
- **多边形 ROI**：形状不规则怎么办？先照着你画的形状剪一张"剪纸"（叫**蒙版**）——
  形状内部涂白、外部涂黑。统计时只算白色盖住的像素，黑色盖住的无视。

### 3. 分析 = 从头到尾给每个时间点"称一次重"

分析过程就像巡逻：

1. 从视频开头开始，每隔一小段时间（约 0.1 秒）取出一帧画面；
2. 对每个 ROI，算出这一帧里该区域的**平均明暗值**；
3. 记下来："几点几分几秒，1 号区域亮度 117，2 号区域亮度 82……"

全部记完后，把这些数字按时间连成线，就是你看到的**亮度曲线**——
哪里变暗了、哪里突然亮了（有人开灯？有手电扫过？），一眼就能看出来。

### 4. 为什么只抽 5000 个点而不是每一帧都算？

一部 1 小时的监控有 5 万多帧。每一帧都算一遍，就像人口普查——精确但慢得要命。
我们改用"抽样调查"：均匀抽取约 5000 个时间点。**对"看趋势、找突变"这种需求，
抽样和普查的结论几乎没有差别**（我们做过严格对比验证：误差不到满量程的 0.3%，
突变出现的时机完全一致），但速度天差地别。

### 5. 为什么现在这么快？

三个杠杆，打个比方：

| 办法 | 类比 | 效果 |
|---|---|---|
| **先看目录再翻书**（导出前抽样） | 以前是把 5 万页全复印下来再挑着看；现在是让复印机只印要看的 5000 页 | 无用功直接消失 |
| **专业设备干粗活**（ffmpeg 解码） | 让复印机（C 语言高速解码）去翻页，人（Python）只做"算平均"这种细活 | 解码提速几十倍 |
| **多人分章节同时干**（分块并行） | 把一本厚书撕成几章，几个人同时复印各自的章节，最后装订回去 | CPU 核数翻倍利用 |

## 二、语谱分析：给声音画一张"地图"

### 1. 声音在电脑里是一长串数字

麦克风把空气的振动变成数字：每秒钟测几千上万次气压，得到一长串数。
比如 1 秒钟的声音 = 24000 个数字。这就是**音轨**。

### 2. 音量曲线：每隔一小段，量一量"劲儿多大"

把这串数字切成一小段一小段（每段约 20 毫秒），算出每段的平均力度（能量），
就得到**音量曲线**——哪里安静、哪里突然有响声，清清楚楚。

### 3. 光有音量不够，还要知道"是低音还是高音"

同样是响，**鼓声（低音）**和**鸟叫（高音）**完全不同。
怎么把混在一起的声音拆开，知道每种高低的音各占多少？

用一个数学工具——**傅里叶变换（FFT）**。把它想象成一台"果汁成分分析仪"：

> 一杯混合果汁倒进去，机器告诉你：苹果汁 60%、橙汁 30%、水 10%。
> 一段混合声音倒进去，它告诉你：超低音多少、低音多少、中音多少、高音多少……

对**每一小段**声音都做一次这个分析，结果就是这一小段的"**频谱**"
（一张成分清单：从低音到高音，每个音高位置的强度）。

### 4. 语谱图 = 把所有小段的成分清单拼成一张图

现在把每一段声音的"成分清单"竖过来，当成**一列像素**：

- **纵轴**：音高（下面低音，上面高音）
- **颜色深浅**：这个音高位置的强度（越亮越响）

然后按时间顺序，把这些像素列从左到右排开——
就得到了**语谱图（频谱图）**：**横轴是时间，纵轴是音高，颜色是响度**。

它就像一张声音的"地图"：

- 一条**水平的亮线** = 某个音高的声音一直在响（比如电流嗡鸣、口哨）；
- 一坨**竖直的亮块** = 某个瞬间的宽频噪声（比如关门、拍桌子）；
- **底噪** = 整张图均匀的暗色背景（空调的嗡嗡声）。

### 5. 两个工程细节（一句话版）

- **为什么要做对数压缩（dB）**：人耳对响度的感觉是"对数式"的——声音强 10 倍，
  你只觉得"响了一些"。原始强度直接画图，微弱的声音会淡得看不见。
  取对数后，轻声细语和鞭炮在图上都能看清。
- **降噪（频谱门控）**：先找几段"本该安静"的部分，量出背景噪声的"指纹"
  （比如空调声在哪个音高、多强），然后全篇统一减掉这份指纹——
  就像擦掉画布的底色，真正的声音事件更突出。

### 6. 实现流水线

```
视频文件 → ffmpeg 抽出音轨、转成统一格式（24000Hz 单声道）
        → （可选）频谱门控降噪
        → 切成 21ms 的小段（段与段之间重叠一半，图更平滑）
        → 每段做 FFT，得到各频率强度
        → 取对数压缩
        → 按时间排列 → 语谱图
```

## 三、分析结果怎么保存（VLA2 格式）

分析完一次不容易，结果要存下来下次直接用。存的东西分两类：

- **"结构性"小数据**：你画的 ROI、标签、辅助线、放大镜位置、截图……
  这些量小、形状不规则 → 用 JSON 文本存（好读好扩展）。
- **"矩阵型"大数据**：几万个时间戳、亮度曲线、音量曲线、尤其是频谱图
  （可能上亿个数字）→ 用**二进制**存，并做两件精简：
  1. **精度按需分配**：亮度曲线需要小数 → 存 4 字节浮点；
     频谱图最终是拿 256 级颜色来显示的 → 直接按 256 级整数存，
     **显示效果一模一样，体积只有原来的 1/8**；
  2. **逐块压缩**：每块数据再压一遍 zlib。

最终效果是：**一个文件装下所有东西**（不再有额外的 `.spec` 伴随文件），
体积比旧格式小 5~10 倍，打开也更快（不用逐字解析海量文本）。
旧版 `.vla` 文件仍然可以正常打开，不用担心历史数据。
