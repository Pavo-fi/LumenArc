## 1. 背景与需求

火调现场常见**多机位同时段监控**（如增城案：正门/后门/厨房多路）。当前
LumenArc 单视频播放：看 A 机 03:00 的画面后，要人工记住时刻再切 B 机找同
时刻——**跨机位"同一墙钟时刻各机画面"对比**全靠人脑拼接。

需求（定稿版）：
1. 独立大窗口，**2-4 路**视频同屏同步播放（无硬性路数门槛，性能自动
   治理见 §4）；
2. 已校时路按**墙钟对齐**（合并时间线：游标指 03:00:00，各路显示各自
   校时后的 03:00:00）；重叠/缺口在时间线上可见；
3. **2 路场景允许一路"临时进"**：没校时的视频手动对一个时间点（画面
   或声音）临时加入同步播放（会话级，不写案）；
4. 含临时进路时用**分开进度条**模式：每路各自带时间的进度条，不显示
   亮度/音量/语谱——纯画面复勘；
5. 每瓦片**独立放大镜**：鼠标悬停滚轮缩放 + 中键拖拽平移；
6. 双击瓦片回主窗单路分析。

## 2. 现状盘点（代码事实，均有落点）

| 资产 | 落点 | 与本需求的关系 |
|---|---|---|
| 单路播放引擎 | `infrastructure/ffmpeg_video_engine.{h,cpp}`（IVideoEngine） | 多实例即可多路；每实例自持解码/音频线程 |
| **D3D11VA 硬解** | ffmpeg_video_engine §54-64/1220-1238（自动回退软解，含硬解回传上屏路径，拖拽追逐已实战验证） | **多路 1440p 的关键底牌**（§4） |
| 倍速播放 | IVideoEngine::setRate（0.25x-8x UI 已暴露，音频随速重采样） | 同步播放直接继承 |
| 拖拽实时追逐 | setScrubMode/setScrubTarget（demux 级追赶） | 合并时间线游标手感复用（U-4 ✅） |
| 多机时间线只读视图 | `multicamview.{h,cpp}`（MultiCamDialog，v1.3 M3） | 墙钟块位/重叠红带/缺口灰纹画风复用 |

| 校时 SSOT | `domain/time_calibration.h` wallMsOf/streamMsOf（分段重建兼容） | 流内毫秒 ↔ 墙钟毫秒双向映射现成 |
| 放大镜交互范式 | `magnifierwidget.{h,cpp}` + OverlayWidget 滚轮/中键（magnifierWheelZoom/magnifierPanRequested） | 交互语义复刻；实现改为瓦片渲染侧裁剪（原 Dock 型太重不复用） |
| 主时钟/状态机范式 | AnalysisTaskService（R7 显式状态机先例） | 同步播放服务照此模式 |
| GPU 显示管线 | P-29 已拍板未施工（DEVELOPMENT_PLAN_V1.6） | 后续性能演进，非本功能前置 |

**现有视图的关键数据缺口**：`CamLane.wallEndMs` 由 `.vla 已分析时长`推出
（块位宽度语义=分析覆盖范围），**不是视频真实全长**。同步播放需要真实
全长（probe duration），装配层需扩展字段。

## 3. 总体架构

```
┌─ ui ───────────────────────────────────────────────────┐
│  MultiCamPlaybackWindow（独立大窗口）                    │
│   ├─ CamTileWidget ×N（2-4 路轻量瓦片：帧显示+OSD+       │
│   │   逐瓦片放大镜[滚轮缩放/中键平移]）                   │
│   ├─ 模式A：合并时间线条（共享墙钟游标，实时追逐）        │
│   └─ 模式B：每路独立进度条（带时间，无分析面板）          │
├─ app ──────────────────────────────────────────────────┤
│  MultiCamSyncService（新增，R7 状态机：                  │
│    Idle→Loading→Ready→Playing/Paused→Ended）           │
│   ├─ 主时钟（单调时钟，按 rate 缩放推进）                 │
│   ├─ 每路 streamMs = cal.streamMsOf(wallMs) 换算        │
│   │   （临时进路 = 会话级偏移映射，见 §3.4）              │
│   ├─ 周期性纠偏（位置轮询 → 微 seek）                    │
│   └─ 性能总督：逐路硬解/软解/lowres 档调度（§4）          │
├─ infrastructure ───────────────────────────────────────┤
│  IVideoEngine × N（R4 引擎中立，禁止 UI 直触实现）        │
└────────────────────────────────────────────────────────┘
```

### 3.1 同步模型

- **统一墙钟轴**：已校时路经各自 .vla 校时映射墙钟；T(wall) 时刻第 i 路
  应显示 `streamMsOf(T)` 处的帧；该路在此墙钟区间无数据（缺口）→ 瓦片
  显示"无信号"占位，不错位硬播。
- **主时钟**：单调时钟（QElapsedTimer + 播放起点墙钟），**不锚定某路音频**。
- **纠偏**：每 250ms 轮询各路 position()，与主时钟换算值偏差 >80ms
  （@20fps 约 1.6 帧）即微 seek 纠正；长 GOP 素材（明景类 12.5s）seek
  代价高 → 纠偏阈值与 GOP 联动放宽（§8 R-2）。
- **倍速**：主时钟按 rate 缩放；各路引擎各自 setRate（既有能力）；倍速
  芯片沿用 0.25x-8x 档。
- **游标手感（U-4 ✅）**：合并时间线拖游标 = 实时追逐（复用引擎
  setScrubMode/setScrubTarget demux 级追赶，与主窗拖拽同手感）。

### 3.2 窗口与两种时间线模式（已拍板）

- **独立大窗口**；入口：现"多机时间线(&M)..."菜单升级；**案件模式与
  独立模式（无案件）均可开**（独立模式走 2 路临时进路径，U-1 ✅）。
- 顶部瓦片网格：2 路 = 1×2 横排；3 路 = 1×3 或 2+1；4 路 = 2×2。
  瓦片为**轻量新控件**（QImage paint + OSD + 放大镜），不复用
  VideoWidget（ROI/快照叠加是多路场景的状态负担）。
- **模式A · 合并时间线**（全部路已校时）：底部多机时间线条（现
  MultiCamViewWidget 画风：块位/重叠红带/缺口灰纹）+ 共享墙钟游标。
- **模式B · 分开进度条**（2 路且含临时进路）：每路瓦片下方各自一条
  **带时间的进度条**（流内时间 + 临时对齐后的推算参考时刻），
  **无亮度/音量/语谱面板**；播放/暂停/倍速仍全路联动。

```
模式判定：
  路数 == 2 且 含临时进路   → 模式B（分开进度条）
  路数 2-4 且 全部已校时    → 模式A（合并时间线）
  3-4 路含未校时路          → 不许进（临时进仅限 2 路界面，Q4 ✅）
```

### 3.3 音频（U-2 ✅：可切听，以声定点）

- 单路主听音（其余静音），**随时点击瓦片切听**（🔊 角标指示当前发声路）；
- **对齐操作场景特别支持**：模式B 手动对齐时，用户可快速切听两路声音
  比对同一声音事件（用户原话："有时候可以通过声音来定对齐点"）——
  对齐会话期间瓦片点击即切听，无额外确认。

### 3.4 临时进路的手动对齐（2 路界面，U-1 ✅ 按草拟）

- 进入：模式B 窗口内"临时加入视频..."选任意 MP4（不要求在案/校时）。
- 对齐操作：临时路拖到/播到可辨认瞬间（画面事件或声音事件）→
  点「以此为对齐点」→ 在另一路进度条上选同一时刻（或手工输入）→
  建立会话级偏移 offsetMs；此后临时路参与联动播放/seek。
- **会话级，不落盘**：不写 .vla、不写 case.json（取证红线——临时对齐
  不是校时，禁止沉淀为案件数据）；关闭窗口即失效；该路以角标明示
  "临时对齐（未校时）"。

### 3.5 瓦片 OSD（U-5 ✅：可选开关）

- 每瓦片角标：路名 + 当前墙钟（临时路：流内时间 + 推算参考时刻 +
  "临时"标）；窗口级开关默认开（汇报演示截图用），可一键关闭。

### 3.6 瓦片独立放大镜（N-7 ✅ 新增需求）

- 交互：鼠标悬停瓦片 + **滚轮** = 以指针位置为中心缩放（1x~8x 档位
  连续）；**中键拖拽** = 平移观察区；缩回 1x 自动复位居中。
  与主窗放大镜同手感（magnifierWheelZoom/magnifierPanRequested 语义），
  但**不弹 Dock**——放大直接在瓦片内渲染。
- 实现：渲染侧裁剪（对已到位的解码帧 QImage 取源矩形放大绘制），
  引擎与解码管线**零改动**；每瓦片独立 zoom/pan 状态。
- 与 lowres 预览档的交互见 §4（lowres 路放大清晰度受限，角标提示）。

### 3.7 回单路分析（U-6 ✅）

双击瓦片 → 主窗 openVideo 打开该路（既有路径），多机窗口可保持打开。

### 3.8 与既有模块的边界

UiState / VideoSessionManager / ChartPanel 等**单视频分析栈完全不动**；
校时数据只读消费（.vla SSOT，R5）；本功能不写任何案内文件。

## 4. 性能治理（U-3 ✅ 定案：不设硬性路数限制，自动降级）

用户拍板"不接受限制不行吗"——定案：**不做"不许进"硬门槛**，改为
三级自动治理（仅影响预览清晰度，不碰任何分析/取证数据）：

| 档 | 触发 | 做法 | 依据 |
|---|---|---|---|
| ① 硬解优先 | 默认 | 逐路请求 D3D11VA（现成路径），GPU NVDEC 多路 1440p 解码轻松 | 引擎 §1220 已有自动回退 |
| ② lowres 预览档 | 软解且总负载超阈（帧率持续不达标） | 该路 `AVCodecContext::lowres=1` 半分辨率解码（≈4×省 CPU）；瓦片实际显示 ≤960×540 时视觉无损 | ffmpeg 通用能力；仅预览降清 |
| ③ 提示 | 仍不达标 | 状态条提示"多路高负载，建议减少路数或降低倍速"，**不强制退出** | C2 不静默 |

- 硬解下 4×1440p@20fps 回传带宽 ≈440MB/s（PCIe 余量内）；软解
  4×1440p 全分辨率会卡是物理事实——lowres 档是兜住"能看"的底线。
- **lowres 路与放大镜**：放大 ≥2x 时清晰度受限（瓦片角标提示
  "预览降清档"）；双击回单路分析不受影响（主窗永远全分辨率）。
- P-29（GPU 显示管线）落地后，①档上屏开销进一步下降，演进不受本
  设计约束。

## 5. 测试策略

- domain：主时钟换算/临时偏移映射/模式判定纯函数单测；分段校时下
  streamMsOf/wallMsOf 一致性（piecewise 套件扩断言）。
- app：MultiCamSyncService 状态机对抗（一路加载失败/缺口区间/纠偏
  触发/倍速切换/临时进偏移/性能降级档切换）——假引擎注入。
- UI 链：ui_chain 扩"开窗→临时进→对齐（含切听）→播→追逐拖游标→
  瓦片放大镜滚轮/中键→双击回单路→关窗"无崩溃断言。
- 真机点检：4 路 1080p 30min 漂移（纠偏后 ≤100ms）；2 路 1440p 明景
  素材（硬解）流畅度；放大镜在各档位的表现。

## 7. 风险与应对

- **R-1 多实例解码稳定性**：引擎长期单实例运行，N 实例并发需压测
  （线程命名/全局 sws/av 无共享状态，理论安全；真机 4 路 1h 老化）。
- **R-2 长 GOP seek 风暴**：纠偏触发 seek 在 12.5s GOP 素材上 = 解码
  至多 250 帧 → 纠偏阈值按 GOP 自适应（§46 探测修复后关键帧间隔
  可知）；>4s GOP 的路阈值放宽 500ms 且只在偏差持续增长时纠。
- **R-3 校时精度天花板**：墙钟对齐精度 = 各路校时精度（rate±0.4% 级，
  30min 可达秒级）——UI 明示"对齐精度取决于校时"；临时进路手动对齐
  精度更低（人眼对帧/对声），角标单独明示。
- **R-4 音频漂移**：主听音路引擎背压/重采样已验证（v1.5+），其余静音。
- **R-5 lowres 切换瞬时黑帧**：解码器重配需重开上下文+seek 续位，
  切换瞬间短暂黑帧可接受；切档加 300ms 迟滞防抖。
