## 1. 背景与需求

火调现场常见**多机位同时段监控**（如增城案：正门/后门/厨房多路）。当前
LumenArc 单视频播放：看 A 机 03:00 的画面后，要人工记住时刻再切 B 机找同
时刻——**跨机位"同一墙钟时刻各机画面"对比**全靠人脑拼接。

需求（2026-08-18 用户拍板版）：
1. 独立大窗口，**2-4 路**视频同屏同步播放；
2. 已校时路按**墙钟对齐**（合并时间线：游标指 03:00:00，各路显示各自
   校时后的 03:00:00）；重叠/缺口在时间线上可见；
3. **2 路场景允许一路"临时进"**：没校时的视频手动对一个时间点，临时
   加入同步播放（会话级，不写案）；
4. 含临时进路时用**分开进度条**模式：每路各自带时间的进度条，不显示
   亮度/音量/语谱——纯画面复勘。

## 2. 现状盘点（代码事实，均有落点）

| 资产 | 落点 | 与本需求的关系 |
|---|---|---|
| 单路播放引擎 | `infrastructure/ffmpeg_video_engine.{h,cpp}`（IVideoEngine） | 多实例即可多路；每实例自持解码/音频线程 |
| 倍速播放 | IVideoEngine::setRate（0.25x-8x UI 已暴露，音频重采样随速变调） | 同步播放直接继承 |
| 多机时间线只读视图 | `multicamview.{h,cpp}`（MultiCamDialog，v1.3 M3） | 墙钟块位/重叠红带/缺口灰纹已有；只读对话框，双击仅发 laneActivated |
| 机位墙钟数据装配 | `app/cam_timeline.{h,cpp}` buildCamLanes | 逐路读案内 .vla 校时 → wallStartMs/wallEndMs |
| 校时 SSOT | `domain/time_calibration.h` wallMsOf/streamMsOf（分段重建兼容） | 流内毫秒 ↔ 墙钟毫秒双向映射现成 |
| 案件视频登记 | CaseVideoRef（id/originalPath/vlaRelPath/cameraLabel/hasCalibration） | 机位清单与校时徽标现成 |
| 主时钟/状态机范式 | AnalysisTaskService（R7 显式状态机先例） | 同步播放服务照此模式 |
| GPU 显示管线 | P-29 已拍板未施工（DEVELOPMENT_PLAN_V1.6） | 多路 1440p CPU 缩放的性能兜底 |

**现有视图的关键数据缺口**：`CamLane.wallEndMs` 由 `.vla 已分析时长`推出
（块位宽度语义=分析覆盖范围），**不是视频真实全长**。同步播放需要真实
全长（probe duration），装配层需扩展字段。

## 3. 总体架构

```
┌─ ui ────────────────────────────────────────────────┐
│  MultiCamPlaybackWindow（独立大窗口）                 │
│   ├─ CamTileWidget ×N（2-4 路轻量帧显示瓦片）         │
│   ├─ 模式A：合并时间线条（现只读视图升级：共享墙钟游标） │
│   └─ 模式B：每路独立进度条（带时间显示，无分析面板）    │
├─ app ───────────────────────────────────────────────┤
│  MultiCamSyncService（新增，R7 状态机：               │
│    Idle→Loading→Ready→Playing/Paused→Ended）        │
│   ├─ 主时钟（单调时钟，按 rate 缩放推进）              │
│   ├─ 每路 streamMs = cal.streamMsOf(wallMs) 换算     │
│   │   （临时进路 = 会话级偏移映射，见 §3.4）           │
│   └─ 周期性纠偏（位置轮询 → 微 seek）                 │
├─ infrastructure ────────────────────────────────────┤
│  IVideoEngine × N（R4 引擎中立，禁止 UI 直触实现）     │
└─────────────────────────────────────────────────────┘
```

### 3.1 同步模型

- **统一墙钟轴**：已校时路经各自 .vla 校时映射墙钟；T(wall) 时刻第 i 路
  应显示 `streamMsOf(T)` 处的帧；该路在此墙钟区间无数据（缺口）→ 瓦片
  显示"无信号"占位，不错位硬播。
- **主时钟**：单调时钟（QElapsedTimer + 播放起点墙钟），**不锚定某路音频**
  （多路音频互不相关，锚定单路让其他路被动漂移）。
- **纠偏**：每 250ms 轮询各路 position()，与主时钟换算值偏差 >80ms
  （@20fps 约 1.6 帧）即微 seek 纠正；长 GOP 素材（明景类 12.5s）seek
  代价高 → 纠偏阈值与 GOP 联动放宽（§8 风险 R-2）。
- **倍速**：主时钟按 rate 缩放；各路引擎各自 setRate（既有能力），
  纠偏阈值不变；倍速芯片沿用 0.25x-8x 档（主窗同款交互）。

### 3.2 窗口与两种时间线模式（已拍板）

- **独立大窗口**，入口：现"多机时间线(&M)..."菜单升级（<2 路可用置灰
  判定复用；2 路含临时进路时也可开）。
- 顶部瓦片网格：2 路 = 1×2 横排；3 路 = 1×3 或 2+1；4 路 = 2×2。
  瓦片为**轻量新控件**（QImage paint + 路名/时间 OSD/无信号占位），
  不复用 VideoWidget（ROI/放大镜/快照叠加是多路场景的状态负担）。
- **模式A · 合并时间线**（全部路已校时）：底部多机时间线条（现
  MultiCamViewWidget 画风复用：块位/重叠红带/缺口灰纹）+ **共享墙钟
  游标**，拖游标 = 全路 seek；游标处各瓦片联动。
- **模式B · 分开进度条**（2 路且含临时进路）：每路瓦片下方各自一条
  **带时间的进度条**（流内时间 + 临时对齐后的推算参考时刻），
  **不显示亮度/音量/语谱面板**；播放/暂停/倍速仍为全路联动。

### 3.3 音频

单路主听音（瓦片点击切换 🔊，其余静音）——多路混音对取证复勘无意义。
（**待确认 U-2**：是否接受单路主听音。）

### 3.4 临时进路的手动对齐（2 路界面，已拍板方向，操作细节待确认）

- 进入方式：模式B 窗口内"临时加入视频..."选任意 MP4（不要求在案、
  不要求校时）。
- 对齐操作（草拟）：临时路拖到/播到 recognizable 的一帧 → 点「以此为
  对齐点」→ 在另一路进度条上选同一时刻（或手工输入该帧对应时间）→
  建立会话级偏移 offsetMs。此后临时路参与联动播放/seek。
- **会话级，不落盘**：不写 .vla、不写 case.json（取证红线——临时对齐
  不是校时，禁止沉淀为案件数据）；关闭窗口即失效。窗口内以颜色/角标
  明示"临时对齐（未校时）"。
- （**待确认 U-1**：对齐交互是否按此草拟；以及临时路是否要求独立模式
  无案件也能开 2 路窗口。）

### 3.5 与既有模块的边界

- UiState / VideoSessionManager / ChartPanel 等**单视频分析栈完全不动**；
  多机播放是独立窗口，双击瓦片可"回到单路分析"（既有 openVideo 路径）。
- 校时数据只读消费（.vla SSOT，R5）——本功能不写任何案内文件。

## 4. 性能预估（诚实账）

| 场景 | 解码负载（软解） | 判定 |
|---|---|---|
| 4× 640×360 DVR | ~4×8% CPU（i7 级） | ✅ 轻松 |
| 4× 1080p | ~4×25% | ⚠️ 可行，需关无关面板 |
| 2× 1440p（明景类） | ~2×40%+ 且每帧 CPU 缩放 ~10ms | ⚠️ 勉强，需真机验证 |
| 4× 1440p | ~4×40%+ | ❌ 需 P-29 GPU Stage 1 先行 |

v1 闸门建议：**1440p 及以上限 2 路**，≤1080p 限 4 路（瓦片按显示尺寸
请求缩放帧）；P-29 落地后放开。（**待确认 U-3**：增城案素材即 1440p，
若实际常需 3-4 路 1440p，则 P-29 需排在此功能之前。）

## 5. 测试策略

- domain 级：streamMsOf/wallMsOf 双向映射在分段校时下的一致性（既有
  piecewise 套件扩断言）；主时钟换算/临时偏移映射纯函数单测。
- app 级：MultiCamSyncService 状态机对抗测试（一路加载失败/一路缺口
  区间/纠偏阈值触发/倍速切换/临时进路会话偏移）——假引擎注入。
- UI 链：ui_chain 扩"开窗口→临时进→对齐→播→拖游标→切主听音→关"
  无崩溃断言。
- 真机点检：4 路 1080p 30min 连续播放漂移量（目标纠偏后 ≤100ms）；
  2 路 1440p 明景素材流畅度。

## 7. （原 §3.1 附）两种模式判定逻辑

```
if 路数 == 2 且 含临时进路 → 模式B（分开进度条）
if 路数 2-4 且 全部已校时  → 模式A（合并时间线）

```

## 8. 风险与应对

- **R-1 多实例解码稳定性**：引擎长期单实例运行，N 实例并发需压测
  （线程命名/全局 sws/av 无共享状态，理论安全；真机 4 路 1h 老化）。
- **R-2 长 GOP seek 风暴**：纠偏触发 seek 在 12.5s GOP 素材上 = 解码至
  多 250 帧 → 纠偏阈值按 GOP 自适应（probe 关键帧间隔已知，§46 探测
  修复后可用）；>4s GOP 的路纠偏阈值放宽到 500ms 且只在偏差持续增长
  时纠。
- **R-3 校时精度天花板**：墙钟对齐精度 = 各路校时精度（OCR/手动采样
  误差率 rate±0.4% 级）。30min 偏移可达秒级——**UI 必须明示"对齐精度
  取决于校时"**，报告引用时同样注明（取证口径）。临时进路的手动对齐
  精度更低（人眼对帧），角标单独明示。
- **R-4 音频漂移**：主听音路引擎自带背压/重采样已验证（v1.5+），其余路
  静音无此问题。
