## 1. 需求（用户口述 2026-08-19）

> OCR 功能已相对完备，希望把「OCR 识别 + 智能排序」重新优化——**之前的还是
> 不太可用**。目标：**初级调查员即看即会即用，最好像之前那样一个「GO」
> 就可以完成操作**。

## 2. 现状盘点（代码事实，均有落点）

### 2.1 现有链路

```
①导入素材 → [开始智能排序] → Probing → OCR(probe_timestamps.py) →
smartSort → ②校对顺序（时间线+证据卡+警告列表）
         → ←/→ 移动 · 手动输入时间… · 重新识别 · 拖拽卡片
         → [确认顺序，下一步] → ③拼接设置 → [开始执行] → ④执行报告
```

- 证据层级：① OCR（像素级真相）> ② 文件名 > ③ 流内绝对时间 > ④
  creation_time > ⑤ mtime（smart_sorter.cpp）；
- 矛盾裁决：两套候选分别排序取连续性误差小者；无法裁决标存疑；
- 强制人工：`suspicious=true`（全组无 OCR 且无流内时间 / 仅 mtime 排序）；
- 已支持：`--roi-json` 用户框选时间戳 ROI（校时通路在用，**批量排序通路
  未接**）；absStart 可信文件走 frames-only 免推理（88× 提速）；
- 已有「直接拼接」旁路（不识别，按列表顺序）。

### 2.2 痛点诊断（为什么「不太可用」）

| # | 痛点 | 实锤落点 |
|---|---|---|
| T1 | **决策点太多**：导入页 2 个按钮（智能排序/直接拼接）→ ②页 5 个操作（←/→/手输/重识别/拖拽）+ 警告列表 → ③页再点一次执行。初级调查员不知道每个决策意味着什么 | buildPageReview 按钮行；四幕强制流转 |
| T2 | **②页是必经关卡**：哪怕 62 段全部 OCR 成功、零冲突，也要人工再点一次「确认顺序」——信任没被折算成自动化 | 四幕状态机 UserConfirm 必停 |
| T3 | **警告用工程师语言**：「与前段缺口 34.2s」「证据①②冲突已按连续性误差裁决」「DurationDubious」——初级调查员看不懂该做什么 | smart_sorter warnings detail 文案 |
| T4 | **未识别段兜底粗暴**：OCR 失败的段没有「最可能位置」推算，基本靠用户自己拖；同机位 62 段里挂 5 段就要手工 5 次 | smartSort 无插值逻辑（grep 实锤） |
| T5 | **同一录像机重复劳动**：同批次 62 段同机位同 OSD 布局，每段都要 6 区块全图找一遍（慢且会挂）；人工框选 ROI 只服务校时，没用到排序上 | crop_blocks 6 区块/段；--roi-json 仅 runAtPositions 用 |
| T6 | **识别失败无就地补救**：②页卡片只有「重新识别」（原样重跑，结果一样）——没有「框一下时间戳再识别」这条最自然的补救路径 | onReIdentify 原参数重跑 |

## 3. 设计目标与红线

**G1 一个 Go**：导入后只点一次，软件自己完成 识别→排序→（可信则）拼接→报告；
**G2 即看即会**：所有文案用调查员语言（「第 5 段没认出时间，请框一下画面上
的时间」而不是「LowConfidence/证据冲突」）；
**G3 可信才自动过**：自动放行必须有硬标准（§4.3），拿不准才停下来问；
**G4 取证红线不动**：源文件只读、OCR 原文逐字保留、人工修正全部留痕进报告；
**G5 不推翻现有架构**：状态机/证据层级/裁决逻辑保留，本方案是「流程编排 +
识别率杠杆 + 兜底策略」三层增强。

## 4. 方案设计

### 4.1 总流程（初级调查员视角）

```
① 把视频拖进来
      ↓ 点一次 [🚀 GO]（原「开始智能排序」升级；「直接拼接」保留为高级旁路）
      ↓ 进度条：正在分析素材（识别画面时间）…
      ↓
┌─ 判定（自动）───────────────────────────────┐
│ A. 全部可信（§4.3 硬标准）→ 直接开始拼接 → 完成页（含结果/播放/报告）│
│ B. 有拿不准的 → 停在「确认页」——只显示拿不准的段，大白话告诉用户做什么 │
└─────────────────────────────────────────────┘
```

**全程零概念的默认路径**：A 路径用户只需要点一次 GO。B 路径用户只处理
「拿不准的段」，处理完点「继续」即拼接。

### 4.2 识别率杠杆：同机位 ROI 自学习（最大收益点）

现场常态：一批素材来自**同一台录像机**（同机位同 OSD 布局）。利用这一点：

1. **首段定版**：对第 1 段做全量识别（现有 6 区块逻辑）；一旦命中，记录
   命中区块的**归一化坐标**作为本批「布局 ROI」；
2. **全批复用**：其余段直接用该 ROI 窄裁剪推理（`--roi-json` 通路已存在，
   只需批量 run() 接上 ROI 参数）——小图推理**快数倍**且**命中率高**
   （不再被画面其他文字干扰）；
3. **失败回退**：某段 ROI 识别失败 → 自动对该段回退全量 6 区块识别
   （C2 不静默，operations.log 记一笔）；仍失败 → 进 §4.4 兜底；
4. **人工定版**：首段也没认出来 → ②页对首段提供「框选时间戳」一键框选
   （复用校时框选组件），框完全批套用；
5. **布局缓存**：按「分辨率+OSD 区块位置」指纹记忆最近一次成功 ROI
   （QSettings），下次同机位素材免学习（会话级/案件级，不落源文件）。

预期收益：62 段同机位批次 OCR 耗时从 ~3-5s/段 降到 <1s/段；识别失败率
显著下降（窄裁剪排除干扰文字——门牌号/广告字是误识别主因）。

### 4.3 自动放行硬标准（可信判定线，全部满足才走 A 路径）

1. 每段都有**排序时间**（OCR / 文件名 / 流内绝对时间 / 兜底插值任一）；
2. 无 Overlap 冲突（时间轴重叠=必须人工裁决的硬矛盾）；
3. 无 EvidenceConflict 未裁决（两套证据矛盾且连续性误差无法区分）；
4. 估算段（§4.4 插值补位）占比 ≤ 20% 且不超过 2 段；
5. 分组数 = 1（多分组=多机位混排，必须人工确认分组归属）。

> 提示级问题不阻断：Gap 缺口（监控本来就会断录）、低置信但有序、
> 时长存疑——这些进报告和完成页醒目提示即可。

### 4.4 未识别段「夹缝插入」兜底（替代现在的手工拖拽）

OCR+文件名+流内时间全挂的段，不再堆给用户自己拖：

1. **夹缝插值**：若该段时长可信，且存在唯一「时间空位」使其前后连续
   （前段.end ≈ 本段.start 且 本段.end ≈ 后段.start，容差 2s）→ 自动插入
   该空位，标记**「估算」**（卡片黄标+报告留痕）；
2. **端点外延**：无可插空位 → 按时长推算放在最前/最后（取连续性误差
   更小一端），同样标「估算」；
3. 估算段参与 §4.3 的占比判定；超占比 → B 路径请用户过目（用户只做
   「确认/调整」而不是「从零排序」）。

### 4.5 B 路径「确认页」重做（只有拿不准时才出现）

现状②页是给工程师的全信息板；B 路径改为任务卡：

- **只列出拿不准的段**（已可信的段折叠为一行「其余 58 段已就绪 ✓」）；
- 每张问题卡三件套：**大字**显示问题（「没认出时间」/「这两段时间重叠，
  哪个在前？」）+ 首帧缩略图 + **就地操作**：
  - 没认出 → [框一下画面上的时间]（框选→单段重识别→自动归位）；
  - 顺序存疑 → 缩略图直接左右拖动，或点 [按拍摄时间自动排]；
  - 实在不要 → [移除这段]；
- 顶部一行进度：「还剩 2 段待确认」→ 清零后主按钮变 [✓ 继续拼接]；
- 底部折叠「查看全部片段」（点开才是现在的完整时间线+证据卡，高级用户用）。

### 4.6 报告与留痕（取证红线）

- 估算段、人工框选段、ROI 自学习命中率全部写进 operations.log + 报告；
- 完成页显示：识别成功 n/估算 m/人工 k，一键打开报告。

## 6. 测试策略

- smart_sorter 纯函数套件：插值/外延/占比判定/警告分级（新增 ~30 断言）；
- coordinator 状态机：可信直通 vs 阻断停驻（task_registry/preprocess 套件扩展）；
- ROI 自学习：mock OCR 结果（首段命中→全批 ROI 下发→失败回退全量）；
- UI 链（mw/preprocess 测试）：GO 一键到拼接执行的全通路 + B 路径问题卡交互；
- 真机回归素材：广州越秀 62 段批次（现成）、后门对面批次、DAV 批次。

## 7. 拍板点（2026-08-19 已全部拍板）

- **Q1 → A**：估算段 ≤20% 且 ≤2 段直接拼（报告醒目标识）；超限才停。
- **Q2 → A**：单一大「GO」主按钮（识别+排序+拼接一条龙）；「直接拼接」
  缩为次要入口。
- **Q3 → 修正（按用户原话）**：「同一次拼接就一台录像机，在这次拼接任务
  中认一次就行」——ROI 自学习**仅本次任务内有效**，不做跨案件/全局缓存
  （无 QSettings 持久化，无指纹校验负担）。
- **Q4 → A**：拿不准时出现「问题卡」页（只列问题段+大白话+就地操作）。
- **Q5 → A**：检测到多机位（多分组）一律停下人工确认。
- **Q6 → 现在做**：排入本批（v1.11），立即施工。

### 原拍板点选项（存档）

- **Q1 自动放行占比线**：估算段 ≤20% 且 ≤2 段可自动过——这个线松/紧？
  （保守方案：任何估算段都停一下让用户扫一眼）
- **Q2 GO 与「直接拼接」关系**：GO 是智能排序一键到底；「直接拼接」保留
  为次要按钮（保持现有旁路）——还是要把两个按钮合一（长按出高级选项）？
- **Q3 布局 ROI 缓存范围**：①仅本次任务 ②案件内记住 ③全局记住——
  换录像机布局不同会不会误套用？（建议②，且带分辨率指纹校验）
- **Q4 确认页形态**：拿不准时才出现的「问题卡」模式（本方案）vs 仍先显示
  全部时间线但自动滚到问题段——初级调查员前者更友好，认可？
- **Q5 多分组**：检测到多机位（多通道）时一律停人工确认（本方案），还是
  分组也可自动（按通道名/首帧画面相似度）？
- **Q6 工作量**：粗估 6-8 人日（排序逻辑 2 + OCR ROI 通路 1 + 确认页 2 +
  测试 1-2）。是否排入下一批（v1.11）？

## 8. 风险

| 风险 | 对策 |
|---|---|
| ROI 自学习把错误布局套全批 → 批量误识别 | 每段结果与邻段连续性交叉验证；异常段自动回退全量识别；命中率进报告 |
| 自动放行放过了错序 | §4.3 硬标准保守；Overlap/冲突必停；报告醒目标识估算段 |
| 初级调查员仍想看到全貌 | 「查看全部片段」折叠入口保留完整②页能力 |
| 夹缝插值插错位置 | 唯一空位才插（多解不外推）；标记估算+报告留痕 |
