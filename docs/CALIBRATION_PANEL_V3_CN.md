# 校时面板 v3 设计方案（拟稿 · 待核对）

> 目标：**流程不变（两步）**，把「说明性文字」压到一行、把「进度」显出来。
> 现状面板 ≈ 900px 高（一屏放不下）；目标 ≈ 420px。
> 本文件只做方案，不改代码。核对通过后按 §六 逐项落地。

## 一、现在乱在哪（6 条，均有截图依据）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **两种流程混在一屏**：第 1 步里塞了 GO、框选、手动单点、手动两点、时间重建、秒级对齐、使用结果、不修正复选 = 8 个操作位 | 面板高度 ≈ 900px，必须滚动 |

## 四、进度显现方案（新增）

### 4.1 显示元素

```
[■■■■■■■■■■■■□□□□□□□□]  读数 12/24 · 约 20 秒
```

- **进度条**：`QProgressBar`，确定进度（有 total）填百分比；不确定阶段（扫秒级/解码）用 `setRange(0,0)` 走马灯。
- **阶段名**：中文短语（下表）。
- **剩余时间**：`已用时长 / 已完成 × 未完成`，**10 秒以上才显示**（否则闪得烦）。
- **完成态**：进度条消失，换成一行结果（`✓ 24 个取样点 · 跨度 1h23m`）。
- **失败/取消**：条变灰/红 + 一行原因 + 一个可点建议。

### 4.2 阶段映射（现在的英文调试串 → 用户语言）

| 服务层现在发 | 界面显示 | 进度类型 |
|---|---|---|
| `sampling` | 取帧… | 不确定 |
| `quick check` | 快速检查表头… | 不确定 |
| `ocr 12/24` | 识别画面时间 12/24 | 12/24 |
| `coarse 28 pts` | 选取样点（28 处） | 不确定 |
| `date-retry merged 3 pt(s)` | 补读日期 3 处… | 不确定 |
| `short-hour repaired 4 pt(s)` | 修复错读小时 4 处… | 不确定 |
| `structured-drop 1 pt(s)` | 剔除异常测点 1 处… | 不确定 |
| `boundary 40 pts` | 对齐分段边界… | 不确定 |
| `tick anchors 30 pts` | 定位秒级锚点 30 处… | 不确定 |
| `tick scan (decode+glyph)` | 逐秒扫描（1~3 分钟） | 不确定 |
| （结束） | ✓ 完成 / ✗ 失败：原因 | — |

### 4.3 服务层建议（小改，向后兼容）

现在 `CalibrationService::progress(QString stage)` 只能塞字符串。建议加一个结构化重载：

```cpp
struct ProgressInfo { int phase; int done; int total; QString note; };
void progress(const ProgressInfo &);
```
界面侧先按 §4.2 映射旧串（不动服务层也能上），后续再把 `ocr done/total` 换成结构化，进度条才有真实百分比。

## 五、交互与边界

| 场景 | 现在 | 建议 |
|---|---|---|
| 识别中 | GO→取消，其余仍可点 | **①②两区全部禁用**（除取消/关闭） |
| 取消 | 停任务 | 保留旧校时值，结果行显示 `已取消，旧结果未变` |
| 重跑 | 直接覆盖 | 已校时后按钮变「重新校时」，**二次确认**（一次跑 1~5 分钟） |
| 关窗 | 后台继续（Q-3 语义） | **不变**（这是对的，别动） |
| 无 ROI | GO 自动找 | 不变 |
| 变速件 | 弹窗确认倍率 | 保留，但按钮文案改「按 1.139× 采用」 |
| 测点明细 | 「查看细节」展开表格 | 移入 **更多 ▾ → 测点明细**（表格不变） |
