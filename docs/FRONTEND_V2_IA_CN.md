# LumenArc 前端 V2 · 信息架构与界面框架

> 状态：**设计稿（待拍板）** ｜ 日期：2026-10-16 ｜ 基线：`e5e75c5`
> 配色：**完全沿用 `src/theme.h` 现有令牌，一个色值都不改**。
> 本文只解决两件事：**业务线怎么分**（信息架构）、**界面怎么搭**（框架）。

---

## 0. 一句话

把「一个主窗口 + 15 个弹窗 + 7 个按动词分类的菜单」
改成「**一个壳 + 六个按办案阶段划分的工作区 + 一条任务带**」。

---

## 1. 诊断：杂乱不是配色问题，是**分类轴错了**

现有菜单的分法是**动词**：文件 / 案件 / 分析 / 产出 / 视图 / 设置 / 帮助。

但调查员脑子里的轴是**「我现在办到哪一步」**。两套轴不重合，于是同一件事被拆散：

| 事情 | 现在在哪 | 问题 |
|---|---|---|
| 素材转码拼接 | 「文件」 | 它是前处理管线的一环，不是"打开文件" |
| 校时 | 「分析」 | 它是所有分析的前置闸门，不该和分析并列 |
| 多机同步播放 | 「分析」 | 它是"看"的方式，不是分析算法 |
| 区域模式（矩形/多边形/辅助线） | 「分析」菜单 | 它是**全局工具状态**，同时被亮度/微变/截图共用 |
| 画面调节 / 截图叠加 | 「视图」 | 它们改的是**显示链**，不是"看哪里" |
| 点位图 | 「产出」 | 它其实是**案件资产**，不是一次性产物 |
| 证据快照 / CSV / DOCX / HTML / 移交包 | 全在「产出」 | 前四个是"导出"，移交包是"交付"，性质不同 |

**结论：现在把四类东西混在一个平面上了。**

| 类别 | 定义 | 应该怎么出现 |
|---|---|---|
| **入口 Gateway** | 把素材弄进来 | 只在「接入」阶段出现 |
| **管线 Pipeline** | 多步骤、有状态、可中断 | 独立工作区，有进度与闸门 |
| **工具 Tool** | 作用于当前上下文，随时可用 | 舞台上的常驻工具条，不是菜单项 |
| **产物 Artifact** | 生成可交付文件 | 按阶段收口，按上下文启用 |

菜单轴 = 阶段。工具按上下文出现，产物到阶段自然解锁。

## 2. 新主线：六个阶段（这是整个前端的骨架）

| # | 阶段 | 用户在这里问的问题 | 主要入口 | 离开本阶段的判据（闸门） |
|---|---|---|---|---|
| 1 | **接入** Ingest | 素材从哪来？ | 打开视频 / 临时查看 / 接入直播 / 新建·打开案件 | 至少一路可播放的素材 |
| 2 | **整备** Prepare | 素材对不对、顺序对不对？ | 前处理（去重/排序/拼接转码）/ 批量重定位 / 机位分组 | 无未决冲突（重叠/缺段/错序） |
| 3 | **校时** Align | 画面时间对不对？ | 三点 / 校时图片 / 北京时间 / 秒级对齐 / 多机事件锚点 | 每路有校准结果，或显式标记"不需要" |
| 4 | **分析** Analyze | 我要看什么？ | 亮度 ROI / 音频+语谱 / 微变 / 多机同步对比 | 至少一条曲线，或显式跳过 |
| 5 | **产出** Produce | 我要出什么？ | 证据快照 / 合成导出 / CSV / DOCX / HTML | 目标产物已生成 |
| 6 | **交付** Deliver | 能不能交出去？ | 完整性校验 / 移交包 / 产物清单 | 校验通过，包已生成 |

**闸门是这套框架的"好用"核心**：阶段条上每格常显三态 —— `✓ 已完成` / `! 有隐患` / `– 未开始`。
点一个未就绪的阶段，不弹错误框，而是给出**「为什么不行 + 一键去补」**。

> 独立模式（不入案）也走同一条主线：接入 → 分析 → 产出，整备/交付自动置灰并说明原因。

## 3. 界面框架：一壳四区

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 工作流条   LumenArc   ①接入 ✓   ②整备 !   ③校时 –   ④分析   ⑤产出   ⑥交付      ⌘K  ⚙ │
├───────────┬──────────────────────────────────────────────┬───────────────────┤
│ 上下文栏   │  舞台 Stage                                   │  检视器 Inspector  │
│ Context   │  ┌────────────────────────────────────────┐   │  ┌─────────────┐  │
│  Rail     │  │                                        │   │  │ 当前选择     │  │
│           │  │   视频 / 工作台 / 表格 / 卡片           │   │  └─────────────┘  │
│ 案件       │  │   （随阶段整体切换，只显示一个）        │   │   属性 …          │
│ ├ 清远     │  │                                        │   │   属性 …          │
│ ├ 增城     │  └────────────────────────────────────────┘   │   属性 …          │
│ └ 顺德     │  ┌────────────────────────────────────────┐   │                   │
│           │  │  时间轴 / 曲线 / 谱图 / 片段时间线       │   │  [ 主操作 ]        │
│ 机位       │  └────────────────────────────────────────┘   │                   │
│ ├ P01     │                                                │                   │
│ └ C11     │                                                │                   │
├───────────┴──────────────────────────────────────────────┴───────────────────┤
│ 任务带  ▸ 校时·秒级对齐 68% ████████░░ 2:41/4:00 [取消]      另有 2 个任务 ▾     │
└──────────────────────────────────────────────────────────────────────────────┘
```

**四个结构性改变：**

1. **同一时刻只有一个工作区。** 现在案件树 + 视频列表 + 图表 + 谱图 + 快照面板 + 画面调节同时挤在 1920 宽里；新框架里它们是「阶段」的产物，不是常驻面板。
2. **上下文栏是"导航"，不是"数据表"。** 它只回答"我在哪个案件、哪一路素材"，不承载操作。
3. **检视器是"上下文敏感"的。** 选中视频 → 视频属性；选中 ROI → ROI 属性；校时阶段 → 测点表；产出阶段 → 片段属性。**永远只有一套属性面板，不随功能各造一个。**
4. **任务带统一所有长任务。** OCR、校时、秒级对齐、转码、渲染、导出全部进同一个队列，可并行、可取消、可追溯。现在它们散在各自的对话框里。

## 4. 六个阶段各自的舞台

### ① 接入
- 三张入口卡片：**打开文件** / **临时查看（不入案）** / **接入直播**
- 下方：最近案件（≤5）+ 拖放区
- 检视器：选中素材 → 编码/分辨率/时长/是否可疑（伪 MP4、负时间戳）

### ② 整备
- 舞台：素材表格（序号 / 文件名 / 画面时间 / 时长 / 状态）+ 冲突标红
- 检视器：问题卡（重叠多少秒、缺段、错序）→ 每个问题一个"修"按钮
- 底部：**GO**（一键编排）与"直接拼接"并列，后者带乱序护栏

### ③ 校时
- 舞台：视频 + ROI 框选（框选即生效）
- 检视器：测点表（时间 / OCR 原文 / 置信 / ⚠ 修正）+ 拟合结果（倍率 / 残差 / 锚点数）
- 底部：时间轴对齐预览（真实刻度 + 缺口红虚线）
- 不再是一个需要"打开/取消/落库"的弹窗——**改就是改，实时生效**（§98 那类"落库的是旧工作面"的 bug 从结构上消失）

### ④ 分析
- 舞台：视频
- 底部：Tab —— 亮度曲线 / 音量曲线 / 语谱图 / 微变云图
- 检视器：ROI 列表 + 参数（灵敏度、平滑、基准段）
- **多机同步/对比 = 舞台切成 2~4 格**，不是另开一个窗口

### ⑤ 产出
- 舞台：合成导出工作台（素材树 → 预览 → 片段块时间线）
- 检视器：片段属性（入出点 / 倍速 / 窗位 / 标注）
- 底部：片段块时间线（拖拽排序、切割、倍速）

### ⑥ 交付
- 舞台：产物清单（快照 / 视频 / CSV / 报告 / 点位图）+ 每项状态
- 检视器：完整性校验结果（哈希 / 缺文件 / 校时可信度）
- 主操作：**导出移交包**

## 5. 状态模型（支撑上面一切）

```
AppState
├── case            : 当前案件 / 独立模式
├── videos[]        : id, 路径, 编码, 时长, 状态
├── activeVideoId   : 当前素材
├── stage           : 六阶段枚举
├── tool            : 选择 / 矩形 / 多边形 / 辅助线 / 平移
├── selection       : 当前选中对象（视频/ROI/片段/文件）
├── tasks[]         : 统一任务队列
├── dirty           : 未保存
└── gates           : 派生，不是手写
```

**两条铁律：**
1. 视图**只订阅**，不持有领域状态。凡是"本地工作面 + 手工落库"的地方，一律删掉。
2. **闸门是派生值**（`gates = f(state)`），不是每个窗口自己 `setEnabled`。

## 6. 命令与工具

- **命令注册表**：每个动作登记一次（id / 标题 / 快捷键 / 启用条件 / 执行）。
  菜单、工具栏、右键菜单、⌘K 面板、快捷键速查表**全部自动生成**。
- **工具状态**从菜单移出，变成舞台上方常驻的 **mode chip**（选择·矩形·多边形·辅助线），
  旁边直接标注「Esc 退出」——模式指示器不再是补丁，而是架构的自然产物。
- **⌘K 保留**，定位从"命令面板"升级为"命令 + 跳转"（跳案件 / 跳阶段 / 跳时间点）。

## 7. 配色与视觉：**只锁色，不动结构**

**不动的**：`theme.h` 全部令牌、Okabe-Ito 数据色板、品牌金 `#F0B429`、深海军蓝 `#16181D`、9pt 微软雅黑 UI。

**要改的（这些不是配色）：**

| 项 | 现在 | V2 |

| 间距节奏 | 各处随手 2/4/6/10 | **4 / 8 / 12 / 16 / 24** 五档 |

## 8. 迁移路径（不冻结功能，每一步都能停）

| 阶段 | 内容 | 风险 | 可独立验收 |
|---|---|---|---|
| **P0 壳与骨架** | `AppState` + `CommandRegistry` + 工作流条 + 任务带 + 舞台容器；**旧窗口先用宿主方式挂进去** | 低 | 是 |
| **P1 接入 + 交付** | 新写（最简单、最独立） | 低 | 是 |
| **P2 校时** | `timesettingsdialog` → 校时工作区 | 中 | 是 |
| **P3 整备** | `preprocesswindow` → 整备工作区 | 中 | 是 |
| **P4 产出** | `composeworkbench` → 产出工作区 | 中 | 是 |
| **P5 分析** | 图表/谱图/多机 → 分析工作区 | 中高 | 是 |

P0 之后，任何一步停住，产品都仍然可用——因为旧窗口还在，只是换了个入口。
